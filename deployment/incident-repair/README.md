# Controlled research incident repair

MB-ARCH-IMPLEMENT-001 L05 implements a typed, private incident ledger and a proposal boundary. Ordinary research does not depend on repair agents being online. Existing provider recovery remains bounded by the original approval, durable attempt admission, deadlines and source rights. The incident recorder never dispatches a replacement call.

The controller accepts only a redacted incident packet. Raw requests, provider response bodies, buyer identity, source excerpts, secret-bearing URLs and runtime environment variables are excluded. The diagnostician may use separately authorized public documentation. A repair executor receives a synthetic reproducer and an exact source scope; its candidate has no network, runtime database, credentials, Docker socket or evaluation oracle. Candidate code executes in a dedicated container with a public-input probe. Only its bounded, schema-validated JSON observations reach a second container containing the protected checks. This evaluator never mounts or imports candidate code, so candidate module mutations cannot modify its assertions or effective oracle. Exit status and candidate-written success strings are not acceptance evidence. Release remains an external, independently reviewed action against the exact candidate.

Worker failure containment and heartbeat teardown precede optional incident recording. Diagnostics use a dedicated checked-out client with a 500 ms acquisition deadline, 750 ms PostgreSQL statement limit, 250 ms lock limit and 2 s total operation deadline. Deadline or error destroys the connection, cancelling pending database work. A timed-out pool acquisition cannot accumulate siblings for the same pool; its eventual client is destroyed. Query-only adapters without bounded connection ownership skip optional retention. These limits do not change provider receipts, the original failure or research authority.

`protocol.mjs` validates incident and patch contracts. It cannot grant tools, spend, modify an oracle or deploy. A diagnosis is not a release authorization. Unknown faults remain contained and queued for controlled investigation; a self-healing guarantee is not asserted.

Run `node deployment/incident-repair/qualify.mjs` from the implementation repository to qualify a seeded defect using the pinned local Node image. This creates and removes isolated containers and a uniquely owned temporary directory, and saves its report outside the source tree. It makes no model/API call. The deterministic repair adapter and fixed six-case development oracle are explicitly a boundary test, not an autonomous foundation-model repair qualification, held-out generalization test or independent human review. Both the broken-seed rejection and repaired-candidate acceptance must pass without changing the oracle or original source. The parent allows at most 8 KiB of candidate output, validates exact fields, case IDs and finite integer values, and passes it as read-only data to the oracle-only container. Candidate execution and grading have separate processes, mounts and module globals.

Production activation of an autonomous repair agent requires its independently authorized tool/model budget, protected evaluation contract, identity, review and release controls. Current local operation records incidents and retains the qualified research path; it does not grant ongoing paid agent access or self-deployment.
